Linux 基础快速回顾 ​

文件系统 ​

路径放什么AI Infra 场景
/home/<user>用户目录代码、conda 环境、缓存（~/.cache）
/etc系统与软件配置/etc/ssh/sshd_config、/etc/fstab、驱动配置
/proc内核暴露的进程/系统信息（虚拟）/proc/<pid>/status、/proc/cpuinfo、/proc/meminfo
/sys设备与内核参数（虚拟）GPU/NUMA 拓扑、温度、功耗
/dev设备文件/dev/nvidia0、/dev/null、/dev/shm
/var/log日志syslog、dmesg、服务日志
/mnt、/media挂载点WSL 里 Windows 盘符挂在 /mnt/c、/mnt/f
/tmp临时文件，重启可能清空编译中间产物、socket 文件
/usr/bin、/usr/local/bin可执行程序python、g++、你自己装的工具
$ ls -lh code/ch01-linux/
-rw-r--r-- 1 sakura sakura  4.2K Nov 12 10:02 inspect_env.cpp
-rwxr-xr-x 1 sakura sakura  21K  Nov 12 10:05 inspect_env
drwxr-xr-x 2 sakura sakura  4.0K Nov 12 10:01 build/

在 ls 命令中：第一列 -rw-r--r-- 代表文件权限和文件类型。第一位代表文件类型：

字母文件类型
-普通文件
d目录文件
l符号链接
c字符设备文件
b块设备文件

如果指定了 --color 参数，文件名可能会带有不同颜色（Ubuntu）：

颜色文件类型
白色普通文件
蓝色目录文件
浅蓝色符号链接（若链接失效为红色）
黄色设备文件
绿色可执行文件
紫色图片文件
红色压缩文件

后九位是三组 rwx，分别对应属主、属组、其他人。r 读、w 写、x 执行（对目录是"能进入"）。第三、四列是属主和属组，第五列是大小，后面是修改时间和文件名。比如，看到 -rw-r--r-- 就可以知道：只有属主能改，其他人只能读。r 权限赋值 4，w 权限赋值 2，x 权限赋值 1，这个权限又可以叫做644。

$ chmod 755 run.sh          # 属主可读写执行，其他人可读可执行
$ chmod +x run.sh           # 给所有身份加执行位
$ chown -R sakura:sakura data/ # 改属主和属组（通常要 sudo）
$ umask
0022                          # 新建文件默认 666-022=644，目录 777-022=755

. 是当前目录，.. 是上级目录，~ 是家目录。以 / 开头是绝对路径，否则相对当前工作目录。程序里的相对路径是相对进程的 cwd（Current Working Directory，当前工作目录，可用 pwd 命令查看），不是相对可执行文件——这是服务启动脚本里最常见的坑之一。

直接运行 ./train.sh 时，内核要求当前用户对文件有 x 权限，并且第一行告诉她用什么解释器：

bash
#!/usr/bin/env bash
set -euo pipefail
python3 train.py "$@"

#!/usr/bin/env bash 比 #!/bin/bash 更可移植：它会在 PATH 里找 bash。脚本里加 set -euo pipefail，让错误尽早暴露，而不是脚本"假装成功"。

-e: 遇到错误立即退出。 如果任意命令返回非零状态码（表示失败），脚本会立即停止执行，避免后续操作可能引发更严重的问题。

-u: 使用未定义变量时报错。 当脚本尝试访问未定义的变量时，会报错并退出，防止因拼写错误或未初始化变量导致意外行为。

-o pipefail: 捕获管道中任何命令的失败。 默认情况下，管道的退出状态只取决于最后一个命令。启用 pipefail 后，如果管道中任意命令失败，整个管道都会被视为失败。

进程与信号 ​

进程是正在运行的程序实例，有独立的 pid、地址空间、打开的文件和环境变量。父进程通过 fork() 复制出子进程，子进程通常马上 exec() 成另一个程序，这就是 shell 执行外部命令的方式。

通过 ps top htop 等工具，可以像 Windows 的任务管理器一样查看 Linux 的进程。例如：

$ ps aux | head -3
USER   PID  %CPU %MEM    VSZ   RSS TTY  STAT START   TIME COMMAND
root     1   0.0  0.1 168000 12000 ?    Ss   09:00   0:02 /sbin/init
$ top -o %MEM          # 按内存排序；q 退出
$ pgrep -af python     # 按名字找 pid，并显示完整命令行
$ ls -l /proc/$(pgrep -f train.py)/fd  # 它打开了哪些文件/端口
# pgrep命令用于根据进程的名称或其他属性来查找和列出匹配的进程ID（PID）

其中 ps 各列的含义是：

列名含义
USER进程所有者的用户名
PID进程号
%CPU进程自最近一次刷新以来，所占用的 CPU 时间和总时间的百分比
%MEM进程占用内存的百分比
VSZ进程占用虚拟内存空间的大小（物理内存和swap都算）
RSS实际驻留物理内存的大小
TTY进程所在终端
STAT进程状态
START进程开始运行的时间
TIME进程占用的总CPU时间
CMD（或 COMMAND）进程启动时的命令

其中进程状态的字符含义如下：

字符含义
D不可中断
R正在运行，或在队列中的进程
S处于休眠状态
T停止或被追踪
Z僵尸进程
W进入内存交换（从内核2.6开始无效）
X死掉的进程
<高优先级
N低优先级
L有些页被锁进内存
s包含子进程
+位于后台的进程组
l多线程，克隆线程

信号是内核投递的异步通知。服务端最关心这几个：

信号编号触发方式能否捕获用途
SIGINT2终端 Ctrl-C能前台程序中断
SIGTERM15kill <pid>能请求优雅退出（默认）
SIGKILL9kill -9 <pid>不能强杀，可能丢数据
SIGHUP1终端断开能传统上让守护进程重读配置
SIGSEGV11非法内存访问能（不推荐）崩溃，交给 core dump/gdb
SIGPIPE13往已关闭的管道/套接字写入能网络服务通常忽略它
